# Установка и первый запуск jevMail

[English version](guides.md)

Это руководство проведёт вас от пустого аккаунта Google Apps Script до
безопасного предпросмотра десяти писем в личной установке jevMail. Скриншоты
расположены в той же последовательности, что и действия.

> [!NOTE]
> Google время от времени меняет названия и расположение элементов в диалогах.
> Если ваш экран немного отличается, ориентируйтесь на названия настроек ниже.
> Ключевые значения развёртывания: **Web app**, **Execute as: Me** и самый
> строгий вариант доступа, доступный для вашего аккаунта.

## Что вы настроите

jevMail работает внутри принадлежащего вам проекта Google Apps Script. Он
считывает выбранные данные писем Gmail, через OpenRouter просит Jev выбрать одну
из настроенных меток и при необходимости применяет метки или архивирует
разрешённые письма.

Вы выполните следующие действия:

1. создадите приватный проект Apps Script;
2. подключите Gmail API;
3. скопируете проверенный исходный код jevMail в проект;
4. развернёте проект как приватное веб-приложение;
5. предоставите необходимые приложению разрешения;
6. подключите API-ключ OpenRouter;
7. запустите предпросмотр, который не изменяет Gmail.

## Перед началом

Подготовьте:

- аккаунт Google с Gmail;
- [аккаунт OpenRouter](https://openrouter.ai/) с небольшим положительным балансом;
- актуальный исходный файл [`CODE.gs`](CODE.gs) из этого репозитория;
- около 10 минут.

Проверьте `CODE.gs` до предоставления доступа. Продолжайте работу после
предупреждения Google о непроверенном приложении, только если **вы самостоятельно
создали проект Apps Script** и скопировали код именно из выбранного репозитория.

## Шаг 1 — Создайте проект Google Apps Script

Откройте [Google Apps Script](https://script.google.com/) в аккаунте Google,
чей почтовый ящик Gmail вы хотите упорядочить. Нажмите **New project**.

![Главная страница Google Apps Script с выделенной кнопкой New project](assets/image1.png)

**Что происходит:** в вашем аккаунте Google создаётся автономный скрипт. Пока
он не развёрнут и не имеет доступа к Gmail.

**Ожидаемый результат:** откроется редактор Apps Script со стандартным файлом
`Code.gs` и небольшим примером `myFunction`.

## Шаг 2 — Присвойте проекту понятное имя

Нажмите **Untitled project** в верхней части редактора, введите `jevMail` и
нажмите **Rename**.

![Диалог Rename Project с названием проекта jevMail](assets/image2.png)

Имя нужно только для поиска проекта в вашем аккаунте Google. Оно не меняет
метки Gmail и URL развёрнутого приложения.

**Ожидаемый результат:** рядом с логотипом Apps Script появится название `jevMail`.

## Шаг 3 — Подключите сервис Gmail API

На левой боковой панели:

1. Нажмите значок **+** рядом с разделом **Services**.
2. Выберите **Gmail API** в списке сервисов.
3. Оставьте версию `v1` и идентификатор `Gmail`.
4. Нажмите **Add**.

![Диалог Add a service с выбранным Gmail API и кнопкой Add](assets/image3.png)

jevMail использует расширенный сервис Gmail, чтобы получать список писем,
читать метаданные и при необходимости текст, создавать и применять метки, а
также удалять метку `INBOX`, когда вы явно разрешили архивацию.

Если проект использует стандартный проект Google Cloud от Apps Script,
добавление сервиса обычно автоматически включает соответствующий API. Для
проекта, связанного с отдельным стандартным проектом Cloud, может также
потребоваться включить Gmail API в Google Cloud Console. Подробнее — в
[руководстве Google по расширенным сервисам](https://developers.google.com/apps-script/guides/services/advanced).

**Ожидаемый результат:** в разделе **Services** редактора появится `Gmail`.

## Шаг 4 — Замените пример кода на jevMail

Откройте `Code.gs`, выделите весь демонстрационный код и замените его полным
содержимым файла [`CODE.gs`](CODE.gs) из этого репозитория. Сохраните проект с
помощью значка дискеты или сочетания клавиш браузера.

![Редактор Apps Script с исходным кодом jevMail](assets/image4.png)

Скопируйте файл целиком, включая функцию `doGet()` и встроенный интерфейс. Не
вставляйте в Apps Script файлы `README.md`, `guides.md`, `server.js` или локальные
тесты. Рабочий интерфейс загружает таблицу стилей из репозитория через jsDelivr,
поэтому отдельный HTML- или CSS-файл в редакторе Apps Script не нужен.

**Ожидаемый результат:** в редакторе отображается код jevMail, а стандартного
примера `myFunction` больше нет. Перед развёртыванием дождитесь подтверждения
сохранения проекта.

## Шаг 5 — Начните развёртывание веб-приложения

В правом верхнем углу редактора:

1. Выберите **Deploy → New deployment**.
2. Нажмите значок шестерёнки рядом с **Select type**.
3. Выберите **Web app**.

![Диалог New deployment с выбранным типом Web app](assets/image5.png)

Веб-приложения Apps Script предоставляют доступ к интерфейсу `doGet()` по URL,
который обслуживает Google. По этому адресу вы будете открывать jevMail.

**Ожидаемый результат:** в диалоге развёртывания появятся поля настройки веб-приложения.

## Шаг 6 — Настройте приватное развёртывание

Укажите следующие значения:

| Поле | Рекомендуемое значение | Зачем |
| --- | --- | --- |
| Description | `jevMail` или примечание о версии | Помогает позднее распознать это развёртывание. |
| Execute as | **Me** | Приложение работает с Gmail аккаунта, который владеет проектом и развёртывает его. |
| Who has access | **Only myself** | Сохраняет личную установку приватной. |

![Развёртывание Web app настроено на Execute as Me и доступ Only myself](assets/image6.png)

Нажмите **Deploy**. Если вариант **Only myself** недоступен в вашем аккаунте
Google Workspace, выберите самое строгое ограничение, разрешённое
администратором, и не передавайте никому URL веб-приложения.

**Ожидаемый результат:** Apps Script предложит авторизовать доступ.

## Шаг 7 — Начните авторизацию Google

Нажмите **Authorize access**.

![Диалог New deployment с выделенной кнопкой Authorize access](assets/image7.png)

Выберите тот же аккаунт Google, которому принадлежат проект Apps Script и ящик
Gmail для обработки. Другой аккаунт может вызвать ошибки доступа или подключить
приложение не к тому почтовому ящику.

**Ожидаемый результат:** Google покажет экран разрешений или сначала
предупреждение о непроверенном приложении.

## Шаг 8 — Безопасно пройдите предупреждение о непроверенном приложении

Личный проект Apps Script не проходил публичную проверку Google, поэтому вы
можете увидеть сообщение **Google hasn't verified this app**.

Если и только если вы сами создали проект и проверили исходный код:

1. Нажмите **Advanced**.
2. Нажмите **Go to jevMail (unsafe)**.

![Предупреждение Google о непроверенном приложении с выделенными Advanced и Go to jevMail](assets/image8.png)

Слово «unsafe» здесь означает, что приватный проект не прошёл публичную
проверку Google. Оно ничего не говорит о безопасности скопированного кода.
Остановитесь, если имя проекта, аккаунт Google или исходный код отличаются от ожидаемых.

Google объясняет этот экран в
[документации о непроверенных приложениях](https://support.google.com/cloud/answer/7454865).

**Ожидаемый результат:** Google откроет подробный экран согласия с разрешениями.

## Шаг 9 — Проверьте и предоставьте необходимые разрешения

Изучите каждое разрешение перед продолжением. Отметьте запрошенные разрешения,
затем нажмите **Continue**.

![Экран согласия Google с разрешениями Gmail и внешнего сервиса](assets/image9.png)

Формулировки на экране могут быть широкими, поскольку область доступа Gmail
API в Apps Script охватывает множество операций. В данной реализации jevMail
использует доступ к Gmail для чтения выбранных писем, создания и применения
меток и необязательной архивации путём удаления метки `INBOX`. Приложение не
вызывает методы отправки, окончательного удаления и перемещения писем в
корзину. Разрешение **Connect to an external service** позволяет скрипту
обращаться к OpenRouter для классификации.

Позднее доступ проекта можно отозвать в разделе
[разрешений аккаунта Google](https://myaccount.google.com/permissions).

**Ожидаемый результат:** авторизация завершится, и Apps Script закончит создание развёртывания.

## Шаг 10 — Откройте и сохраните URL веб-приложения

После успешного развёртывания используйте адрес в разделе **Web app**. Нажмите
на URL, чтобы открыть jevMail, либо нажмите **Copy** и вставьте адрес в новую
вкладку браузера. Не передавайте этот URL посторонним.

![Диалог успешного развёртывания с выделенным URL Web app](assets/image10.png)

Рабочий URL обычно заканчивается на `/exec`. Адрес `/dev` из раздела **Test
deployments** предназначен для разработки и доступен только пользователям,
которые могут редактировать скрипт.

Сохранив URL, нажмите **Done**. Позднее адрес можно найти в разделе
**Deploy → Manage deployments**.

**Ожидаемый результат:** панель jevMail откроется в новой вкладке.

## Шаг 11 — Откройте панель подключения OpenRouter

На первом экране находятся настройки подключения OpenRouter и обработки.

![Панель jevMail с подключением OpenRouter и безопасными настройками обработки](assets/image11.png)

Нажмите **Create API key**, чтобы открыть страницу ключей OpenRouter в новой
вкладке. Её также можно открыть напрямую:
[OpenRouter Keys](https://openrouter.ai/workspaces/default/keys). Войдите в
аккаунт OpenRouter, с которого будет оплачиваться использование модели jevMail.

Не закрывайте вкладку jevMail, чтобы вернуться к ней после создания ключа.

**Ожидаемый результат:** OpenRouter откроет страницу API Keys рабочего пространства по умолчанию.

## Шаг 12 — Создайте ограниченный ключ OpenRouter и выполните безопасный предпросмотр

На странице OpenRouter API Keys нажмите **New Key**. Создайте отдельный ключ для
этой установки вместо повторного использования универсального ключа.

![Диалог создания ключа OpenRouter со сроком действия и пользовательским лимитом](assets/image12.png)

### Настройте ключ

Безопасные начальные значения:

| Поле | Рекомендуемое значение для первого запуска | Назначение |
| --- | --- | --- |
| Name | `jevMail` | Позволяет легко распознать использование и отозвать ключ только этого приложения. |
| Expiration | `30 days` | Ограничивает срок действия скопированного или забытого ключа. После проверки продлите срок или замените ключ. |
| Credit limit | `Custom amount` | Включает отдельный лимит расходов для ключа. |
| Custom amount | `$1` | Даёт достаточно средств для тестирования и ограничивает общие расходы этого ключа в OpenRouter. |
| Reset limit every | `N/A` | Считает $1 общим лимитом, пока вы не увеличите его вручную. |
| Include BYOK usage in limit | Off | Оставьте выключенным, если вы не подключили собственные ключи поставщиков и не хотите учитывать их использование в этом лимите. |

Сумма указывается в долларах США. При значении **Reset limit every: N/A**
OpenRouter отклоняет новые запросы после полного расходования установленной
суммы. Если вам нужен возобновляемый бюджет, выберите ежедневный, еженедельный
или ежемесячный сброс; по документации OpenRouter такие лимиты автоматически
обновляются в полночь по UTC.

> [!IMPORTANT]
> Лимит ключа OpenRouter и настройка jevMail **Maximum processing cost** решают
> разные задачи. Лимит OpenRouter ограничивает использование ключа во всех
> запусках. Настройка jevMail служит консервативным ограничителем одной сессии
> обработки. Оставьте обе меры включёнными.

Завершите создание ключа и сразу скопируйте полное значение `sk-or-v1-...`.
OpenRouter показывает ключ открытым текстом только в момент создания. Не
добавляйте его в `CODE.gs` или GitHub, не показывайте на скриншотах и не
передавайте другим людям.

Лимит можно изменить позднее на странице API Keys. Там же можно отключить или
удалить только ключ jevMail, не затрагивая ключи других приложений. Актуальное
поведение лимитов и сбросов описано в
[документации API-ключей OpenRouter](https://openrouter.ai/docs/api/api-reference/api-keys/create-keys).

### Подключите новый ключ к jevMail

1. Вернитесь на вкладку jevMail.
2. Вставьте ключ в поле **OpenRouter API key**.
3. Оставьте включённым **Store this key in Apps Script User Properties for
   future sessions**, если хотите сохранить ключ в пользовательских свойствах
   Google Apps Script. Снимите флажок, чтобы хранить его только в текущей вкладке браузера.
4. Нажмите **Verify connection**.

При успешной проверке отобразятся выбранная метка, уверенность и расчётная или
фактическая стоимость запроса. Используйте лимит расходов ключа или аккаунта
OpenRouter как дополнительную защиту бюджета.

### Выберите настройки первого запуска

Используйте небольшую и безопасную проверочную выборку:

| Настройка | Значение для первого запуска |
| --- | --- |
| Email source | `Inbox` |
| Message limit | `10 — validation sample` |
| Maximum processing cost | `$0.01–$0.10` |
| Processing mode | `Apply labels only` |
| Process unread messages only | Enabled |
| Preview only | Enabled |

В режиме предпросмотра выбранные данные писем отправляются на классификацию, но
приложение не создаёт и не применяет метки и не архивирует письма в Gmail.

### Проверьте систему меток

Откройте **Labels** на боковой панели. Набор **Universal inbox** —
сбалансированный вариант по умолчанию для смешанной личной и рабочей почты. Вы
можете выбрать специализированный набор, нажать **Load into editor** и изменить
любую метку и любой критерий.

Перед обработкой убедитесь, что:

- категории описывают наблюдаемые признаки, а не абстрактную важность;
- пересекающиеся категории содержат чёткие исключения;
- резервная метка `review` остаётся доступной для неоднозначных подлинных писем;
- **Archive eligible** включено только для низкорисковых нежелательных категорий.

После редактирования нажмите **Save classification rules**.

### Запустите и проверьте предпросмотр

Откройте **Message processing** и нажмите **Start processing**. Не закрывайте
вкладку во время сессии. Проверьте:

- выбранную метку для каждого письма;
- уверенность Jev;
- было ли решение принято по метаданным или полному содержимому;
- предполагаемые действия Gmail;
- общую стоимость обработки;
- сообщения об ошибках.

Если письма попадают не в те категории, измените описания меток. Когда
предпросмотр станет стабильно полезным, отключите **Preview only** и запустите
ещё одну выборку в режиме **Apply labels only**. Включайте **Apply labels and
archive eligible messages** только после нескольких проверок на реальных
письмах. Архивация удаляет метку `INBOX`, но не удаляет письмо: оно остаётся в
разделе «Вся почта».

## Последующее обновление jevMail

1. Откройте существующий проект Apps Script.
2. Замените содержимое `Code.gs` новой проверенной версией [`CODE.gs`](CODE.gs).
3. Сохраните проект.
4. Откройте **Deploy → Manage deployments**.
5. Отредактируйте существующее развёртывание веб-приложения.
6. Выберите **New version**, затем нажмите **Deploy**.

Существующий URL `/exec` останется точкой входа. Сохранённые правила и API-ключ
останутся в Apps Script User Properties, пока вы не удалите их в приложении или
не удалите сам проект.

## Устранение неполадок

### Ошибка `Gmail is not defined`

Не подключён расширенный сервис Gmail. Повторите шаг 3 и убедитесь, что `Gmail`
появился в разделе **Services**.

### Страница сообщает, что требуется авторизация

Откройте развёртывание, войдя в аккаунт владельца проекта, и выполните шаги
7–9. Администраторы Google Workspace могут ограничивать Apps Script или внешние
запросы; если экран согласия заблокирован, обратитесь к администратору.

### Веб-приложение показывает старую версию

Одного сохранения `Code.gs` недостаточно для обновления существующего рабочего
развёртывания. Создайте новую версию развёртывания по инструкции выше, затем
перезагрузите URL `/exec`.

### В интерфейсе нет оформления или логотипа

Развёрнутая страница должна загружать публичные ресурсы с GitHub через jsDelivr.
Убедитесь, что репозиторий публичный, файл `style.css` существует в ветке `main`,
а браузер или сеть не блокируют CDN.

### Не проходит проверка OpenRouter

Убедитесь, что ключ скопирован полностью, активен и имеет доступный баланс.
Проверьте [историю OpenRouter](https://openrouter.ai/activity) и лимиты расходов
ключа. Сохранённый ключ можно удалить кнопкой **Remove saved key**, а затем
подключить заново.

### Обработка останавливается на лимите стоимости

Незавершённые письма остаются без изменений. После проверки предыдущих
результатов и истории OpenRouter начните новую сессию с подходящим бюджетом.

## Контрольный список безопасности

- Разворачивайте приложение из проекта, который принадлежит вам.
- Оставьте для **Who has access** самое строгое доступное ограничение.
- Не передавайте URL развёртывания посторонним.
- Используйте отдельный ключ OpenRouter с лимитом расходов.
- Начните с **Preview only** и **Apply labels only**.
- Проверьте результаты на репрезентативной выборке до включения архивации.
- Если вы перестали пользоваться приложением, отзовите доступ Google и удалите
  сохранённый ключ OpenRouter.

Обзор продукта, модель конфиденциальности, готовые наборы меток и технические
ссылки доступны в [русской версии README jevMail](README-ru.md).
